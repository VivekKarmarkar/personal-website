Introduction

You're running Claude Code on your laptop. You tell it to go play an educational simulation. Your Claude Code opens an SSH tunnel to a cloud server and launches a second Claude Code instance on the other side — authenticated via OAuth against your Claude Max subscription, running with --dangerously-skip-permissions, with a real Chromium browser at its disposal. That's the inception: Claude Code spinning up Claude Code on a separate computer, handing it a prompt, and walking away.

The remote Claude Code wakes up inside a DigitalOcean VM with a virtual 1920×1080 display and no physical monitor. It reads a config file that tells it what tools are available — one of those tools is a Playwright server that gives Claude direct control of Chromium. From there, Claude navigates to the simulation, reads the page through accessibility snapshots, clicks buttons, drags sliders, and reasons about what it sees — narrating every decision. A split-screen layout captures both sides: Claude's terminal output streams on the left, the browser fills the right. Meanwhile, ffmpeg records the entire virtual display at 30 frames per second. You can close your laptop. The VM doesn't need you.

When Claude finishes exploring, the script finalizes the recording, loops a lo-fi music track underneath with faded transitions, and produces a formatted commentary transcript. One command in, one video out.

That recording is useful in two very different ways. The first is educational game design testing. Claude approaches every simulation like a first-time student — no prior knowledge, no curse of expertise. When a simulation is poorly designed — drag-and-drop as the only interaction mode, no scaffolding, unclear feedback — Claude fails immediately and obviously. It becomes a stress test for your UX: if Claude can't figure out what to do, a confused student won't either.

The second is a novel benchmark for AI capabilities. Even on beautifully designed simulations, Claude stumbles. It can write you a flawless textbook explanation of any physics concept, but when it's staring at an interactive simulation and needs to predict what will happen next — where an object will move, how a force diagram will change — it has been observed to hallucinate at times. The gap between verbal fluency and spatial reasoning is stark — and interactive science simulations test exactly the skills that text-based benchmarks miss.

And the architecture itself — an AI agent running autonomously in an isolated cloud container with full permissions and nothing to break — is a reusable pattern for autonomous AI work far beyond educational games.

The Closed Laptop Test

If your laptop can be shut and the work still happens, the autonomy is real. Everything in this architecture serves that principle.

The VM doesn't need your machine to stay connected. The recording doesn't need you to watch. The commentary doesn't need you to prompt. Claude makes its own decisions about what to click, when to re-read instructions, whether to try a different approach. The agent runs with --dangerously-skip-permissions — not because we're reckless, but because the VM is an isolated container with nothing to break. That isolation is what makes full autonomy safe. The dangerous flag becomes a feature, not a risk, when the environment is disposable.

But making it work required unexpected setup steps downstream. Autonomous AI sounds like a dream until you're three iterations deep into a problem you didn't know existed. Every Claude Code power user has been there — the strange, problem-specific blocker that takes a few more unplanned rounds to solve. That's exactly what happened here, and the solutions are baked into the pipeline so you never hit them again.

The B-Minus Student

Claude behaves like a B-minus student. Strong conceptual knowledge, weak at verifying what's actually on screen versus what it expects to see.

It hallucinated thermal energy in the Energy Skate Park simulation when friction wasn't even toggled on, then declared everything was working perfectly. It confidently narrated physics that wasn't happening.

It got the correct answer on a sequence convergence problem but knew it wasn't optimal, which drove genuine retry behavior.

This is the gap that makes educational simulations a novel AI benchmark. Claude can write you a flawless textbook explanation of any physics concept. But put it in front of a simulation that requires spatial reasoning — predicting trajectories, understanding force diagrams, interpreting visual transformations — and the confident verbal fluency falls apart. Existing AI benchmarks test text, code, and multiple-choice reasoning. Interactive science simulations test something none of them cover: can the model actually do the physics it claims to understand?

PhET has 160+ open-source simulations spanning elementary school through graduate-level physics. That's a ready-made curriculum of increasing difficulty — a benchmark suite that's reproducible, publicly accessible, and tests capabilities that matter in the real world. The pipeline already works. The evaluation framework is the contribution.

What Makes a Simulation Work

After running the agent through nine different simulations — PhET physics sims, custom-built math games, third-party educational tools — three design principles emerged that predict whether Claude will succeed or fail.

Multiple affordances. If the simulation offers visual, numerical, and interactive paths to the same concept, the agent finds its way even when one path is blocked. Simulations with a single interaction mode — especially drag-and-drop — consistently produced failures.

Gradient of success. Binary pass/fail kills engagement. The best simulations have a sweet spot where the agent's answer is correct but not optimal, creating a natural drive to try again. Claude re-engaged most enthusiastically with simulations that rewarded partial understanding.

Immediate feedback. Click, result, learn. No waiting, no ambiguity about whether an action had an effect. The simulations where Claude struggled most were the ones where the connection between action and outcome was delayed or unclear.

These aren't just AI findings. They're the same principles that make educational software work for human students. The agent just makes them measurable.
